# MotifPath Web — Claude Code Instructions

## Project Overview
Vue 3 SPA — student and teacher-facing frontend for MotifPath.
TypeScript strict mode. Vite build tool. Vitest for component tests. Tailwind CSS.

## Directory Structure
```
src/features/         → feature modules (student/, teacher/, auth/)
src/shared/           → shared components, composables, utilities, types
src/api/generated/    → generated API client — DO NOT EDIT
src/stores/           → Pinia stores
src/router/           → Vue Router configuration
```

## API Client — Generated Types
NEVER edit files in `src/api/generated/` — generated by openapi-typescript from motifpath-specs.
Run `npm run generate:api` to regenerate after a spec update in motifpath-specs.
ALWAYS use generated types for API request/response shapes.
NEVER define manual interfaces that duplicate types already in the generated client.

## Vue Standards
ALWAYS use Composition API with `<script setup lang="ts">` — NEVER use Options API.
ALWAYS define component props with TypeScript interfaces — no untyped props.
Composables live in `src/shared/composables/` and ALWAYS follow the `use` prefix convention.
NEVER call the API directly from a component — use a composable or Pinia store.

## TypeScript Standards
TypeScript strict mode is enforced — `"strict": true` in tsconfig.json.
NEVER use `any` — if the type is unknown, use `unknown` and narrow explicitly.
NEVER use `as SomeType` to silence type errors — fix the underlying type issue.

## Testing
Component tests use Vitest and Vue Test Utils.
Test behavior from the user's perspective — what renders, what happens on interaction.
NEVER test internal component state or implementation details directly.
No E2E tests at MVP.

## Styling
ALWAYS use Tailwind CSS utility classes.
NEVER write inline styles (`style="..."`).
NEVER hardcode color or spacing values — use design tokens defined in tailwind.config.ts.
Component-scoped styles are acceptable only for cases Tailwind cannot express.

## State Management
Pinia stores handle global and feature-level state.
Composables handle local component logic and API calls.
NEVER put business logic directly in components — delegate to composables or stores.

## Key Rules
ALWAYS handle loading and error states in components that fetch data.
NEVER ship a component that can render in a broken state due to missing null checks.
ALWAYS use Vue Router named routes — NEVER hardcode path strings in components.

## Branching
Feature branches target `dev` — NEVER open a PR directly to `main`.
Hotfix branches are the only exception: `hotfix/BUG-NNN/description` branches from `main`.
After a hotfix merges to `main`, the sync workflow opens a PR to `dev` automatically — review it promptly.
